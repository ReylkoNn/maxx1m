# Выбор криптографического протокола: предварительная оценка

Состояние на 2026-11-06. Это техническая оценка, а не юридическое заключение,
аудит или выбор версии зависимости для production.

- [libsignal](https://github.com/signalapp/libsignal) содержит реализацию Signal
  Protocol, в том числе Double Ratchet. По upstream README продуктовые интерфейсы
  предназначены для Java, Swift и TypeScript; использование вне Signal не
  поддерживается, API и bridge могут меняться. Официального поддерживаемого Python
  интерфейса в README нет. Репозиторий распространяется под AGPL-3.0. Нужны
  оценка совместимости лицензии, воспроизводимая сборка моста для каждой ОС и
  сопровождение его обновлений. Случайный Python-пакет с похожим названием нельзя
  считать официальным или проверенным.
- [OpenMLS](https://github.com/openmls/openmls) реализует MLS (RFC 9420), а не
  Signal Protocol; upstream заявляет Rust-интерфейс и MIT-лицензию. Для Python
  потребуется отдельно поддерживаемый bridge, проверка сборок и надёжное
  транзакционное хранение состояния. MLS сам по себе не решает проверку личности,
  доставку, мультидевайс и последовательность изменения членства.

До выбора и проверки конкретных версий новые зашифрованные группы не включать.
Нельзя заменить эту работу использованием имеющихся статических ключей или
переключением флага. Перед внедрением необходимы:

1. Решение по лицензиям и целевым платформам, закреплённые версии и проверка
   исходников/сборок мостов; тесты обновлений и отказов при сохранении состояния.
2. Протокол привязки identity keys к устройствам и сверки их пользователями,
   обработка отзыва и изменения ключей без автоматического доверия серверу.
3. Серверное хранение и маршрутизация prekey/MLS сообщений без доступа к секретам,
   атомарное сохранение локального состояния перед подтверждением доставки.
4. Тесты параллельных сообщений, пропусков и повторов, офлайна, перезапуска,
   смены состава групп, устройств и потери состояния; независимый аудит.
5. Отдельный план миграции и прозрачное отображение пользователю: старая история
   и старые клиенты не получают прямую секретность задним числом.

Связанные ограничения эксплуатации — в [turn-and-groups.md](turn-and-groups.md).

## Результат пробного моста

В [изолированном эксперименте](../experiments/openmls-probe/README.md) запущен
зафиксированный экспериментальный `openmls-wasm@0.1.0`, а Python вызывает только
его синтетическую самопроверку через subprocess. Базовый обмен двух участников
получился, но в этой обёртке выявлены блокеры: существующий участник не применяет
commit добавления третьего, не представлены удаление и долговечное сохранение,
а обработка повреждённых данных может оставлять объект непригодным или мешать
обработке оригинального сообщения. Это наблюдения конкретного старого пакета,
не вывод обо всех версиях OpenMLS. В текущей среде Rust toolchain отсутствует;
реальный Python/Rust bridge для актуального OpenMLS здесь не собран. Группы
остаются отключены.

Проверка [документации OpenMLS 0.9.0](https://github.com/openmls/openmls/blob/openmls-v0.9.0/book/src/user_manual/processing.md)
показывает, что приложение должно сохранять полученный `QueuedProposal` в
proposal store перед обработкой связанного commit. Экспериментальная WASM-обёртка
этого не делает; это объясняет наблюдаемый отказ, но не является исправлением.
Доступного Rust-компилятора и доступа к crates.io в этой среде нет, поэтому
актуальный OpenMLS и мост с исправлением здесь не собраны и не проверены.


## Предварительное исследование X3DH и Double Ratchet (не внедрено)

Дополнительно изучены независимые MIT Python-пакеты `x3dh==1.3.0` и
`doubleratchet==1.3.0`, заявляющие поддержку авторами. Это не libsignal; их
независимый аудит и соответствие артефактов исходникам не установлены.
[Изолированная воспроизводимая проба](../experiments/ratchet-probe/README.md)
проверяет синтетический обмен и выявляет блокеры: расход одноразового prekey
до проверки ciphertext, потерю отложенных сообщений при превышении порога
пропусков на смене цепочки, а также необходимость проверить сравнение HMAC-тегов
на устойчивость к timing attacks. Приём, очередь и состояние потребуют единой
транзакции; текущая static-Box проверка повтора не работает для ratchet.
Код пробы не подключён к приложению, пункт 3 не завершён.
