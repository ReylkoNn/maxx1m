# OpenMLS: изолированный эксперимент, не реализация групп

**Не использовать с настоящими сообщениями, идентичностями или ключами.**
Этот каталог не подключён к Max1m, не открывает группы и не является мостом
для реального чата. `probe.py` запускает только фиксированный автономный
синтетический тест и возвращает булев отчёт. Он не принимает входные сообщения
или данные пользователей. Node-процесс и его состояние уничтожаются при выходе.

## Запуск

Требуется Node.js 22+ и Python 3; для установки требуется доступ к npm:

```sh
cd experiments/openmls-probe
npm ci --ignore-scripts --no-audit --no-fund
npm test
python probe.py
python -m unittest discover -s test -p 'test_*.py' -v
```

Проверено только на Linux x86-64 с Node 22.22.3. Node предупреждает, что
используемый механизм импорта WASM экспериментальный. `package-lock.json`
фиксирует пакет `openmls-wasm@0.1.0` и его integrity hash; это защищает от
незаметного изменения скачанных байтов, но не доказывает соответствие бинарника
исходникам или отсутствие уязвимостей. В npm пакет указывает репозиторий OpenMLS
и gitHead `e058b953567bf7b05148e7e142d08d96e3246ff5`. В самом upstream он
описан как [экспериментальная обёртка](https://github.com/openmls/openmls/tree/e058b953567bf7b05148e7e142d08d96e3246ff5/openmls-wasm),
не готовая для production. Это старый пакет, **не** OpenMLS 0.9.0 и не доказанная
реализация Signal Protocol. Node и Python не добавлены в runtime приложения.

## Наблюдения на этой версии

- Два созданных в памяти участника обмениваются тестовыми сообщениями, повтор
  принятого ciphertext отклоняется, другой тестовый ключ не принимает Welcome.
  Это узкие проверки, не аудит и не доказательство полной безопасности.
- При добавлении третьего участника существующий участник обрабатывает proposal,
  но не может применить ссылающийся на него commit. Судя по исходникам обёртки,
  она возвращает пустой результат для proposal, не сохраняя его. Тест фиксирует
  это наблюдение как **блокер**, а не как успешный сценарий смены состава.
- Изменённый ciphertext отклоняется, однако последующая обработка оригинального
  пакета с тем же счётчиком в нашем тесте также завершается ошибкой об удалённом
  секрете. Нужен анализ версии, гарантий OpenMLS и границ транзакции/rollback;
  эксперимент не позволяет делать общий вывод обо всех версиях OpenMLS.
- Некорректный пакет `[0]` приводит к WASM trap; после него дальнейшая обработка
  на том же объекте в нашем тесте невозможна. Реальное приложение должно
  переживать недоверенные входные данные и не терять сохранённое состояние.
- Публичный API пакета не предоставляет операции удаления участника и сохранения/
  восстановления группы и идентичности. Тестов удаления, исключения бывшего
  участника, рестарта и безопасной долговечной доставки здесь **нет**.

Тесты с пометкой `KNOWN BLOCKER` воспроизводят известное нежелательное поведение;
их зелёный статус означает только, что блокер воспроизведён. Тесты `TODO` не
выполняются. Никаких обещаний о готовности к эксплуатации из них не следует.

## Что нужно для реального моста

Нужны поддерживаемая версия библиотеки и собственный минимальный Python/Rust
bridge с сериализацией MLS-объектов, обработкой proposals/commits и удалением,
проверкой учётных данных на входе, защищённым транзакционным хранилищем и
атомарной связью обновления состояния с очередью и подтверждениями. Необходимо
закрепить зависимости, проверить платформенные сборки, протестировать конфликты
commit, обработку некорректных входных данных, rollback и провести аудит. Затем
разработать серверную маршрутизацию и миграцию. Экспериментальный WASM-пакет
не следует подключать к продукту в качестве обходного решения.
